# ALLS Configurator 设计说明

`Alls.Configurator` 是独立发布的 .NET 8 WPF 桌面程序，运行时不依赖 Bootstrapper
可执行文件。项目在编译期链接 Bootstrapper 的两个配置模型源文件，因此配置字段、枚举值和
默认值保持同源，不需要维护第二套 DTO。

## 信息架构

- **概览与显示**：品牌资源、语言、窗口布局、启动入口和日志。
- **游戏**：菜单信息、启动命令、进程/窗口监控、更新、退出行为和游戏专用时间线。
- **默认时间线**：未设置游戏专用时间线时使用的 STEP 序列。
- **输入设备**：输入总开关、键盘调试、热插拔间隔和 HID 设备列表。
- **更新源**：HTTP 与 USB 更新源及认证、目录、超时设置。
- **机台操作**：内置操作和自定义命令、确认提示。
- **校验与 JSON**：结构化问题列表及最终序列化结果。

列表编辑器统一提供添加、复制、删除和排序。启动配置器时若传入 JSON 路径，会直接打开该
文件；未传路径时会尝试打开配置器同目录的 `alls-launcher.json`。

窗口支持拖动边框或右下角尺寸手柄调整宽度和高度，通常可缩小至 640×480（WPF
逻辑尺寸）；初始尺寸及最小尺寸会限制在主屏幕工作区内。工具栏随宽度自动换行，
编辑区保留表单所需宽度并在窄窗口下提供横向滚动条，避免标签和输入框被挤压。
长表单、默认时间线、输入设备、更新源及校验预览提供纵向滚动，便于在较低窗口内访问所有字段。

编辑区宽度按窗口可用空间计算，并保留 1160 的最小内容宽度。横向滚动容器内必须提供
明确的有限宽度，避免表格的 `*` 列在无限宽度下计算异常。时间线消息列和校验说明列
保留可读的最小宽度；表格支持拖动列标题边界调整列宽，内容超出表格时使用内部横向滚动条。

游戏启用自动更新后，Bootstrapper 会在时间线中插入或复用 STEP 12 安装阶段，
无需在配置器里额外添加更新动作；实际位置和跳过行为见[配置说明](configuration.md#updatesources-与游戏自动更新)。

配置项标题旁的“？”提供详细用途说明，悬停即可查看，不占用表单空间；字符串枚举在界面中
使用中文含义展示，但写入 JSON 时仍保持原有英文枚举值。工作目录、游戏更新目标目录、
U 盘更新目录等本地目录字段可通过“浏览”按钮选择。HTTP 更新源的 `path` 是 URL 相对路径，
因此仍需手动输入。

HTTP 更新源提供“服务器连接不可用时算失败”，默认勾选。个人电脑上的临时更新服务器可
取消勾选：首次连接不可用时按普通状态跳过，仍继续尝试后续来源；收到响应后发生的目录
读取或下载错误仍算失败。切换成 USB 来源时隐藏此选项，其保存值不影响 USB 更新。

游戏的更新源引用使用“选择—添加”列表维护，并可调整尝试顺序。引用的更新源被删除或改名
后，原 ID 会保留并在游戏编辑页标红，配置检查会将其作为错误并阻止保存，直到用户移除该
引用或重新建立同 ID 的更新源。

## 数据与保存策略

- 读取兼容大小写不敏感字段、注释和尾逗号。
- 写入使用 camelCase、字符串枚举、UTF-8 无 BOM 和缩进格式。
- 写入先落到同目录临时文件，再替换目标文件。
- 覆盖已有配置前复制为 `<文件名>.bak`。
- 未保存内容在新建、打开和关闭窗口前均会提示。
- 空字符串列表编辑器支持换行、逗号和分号分隔，并自动去重。

## 保存前校验

错误会阻止保存，警告不会。当前检查包括：

- 游戏、更新源和操作 ID 的必填与唯一性；
- 默认游戏和游戏所引用更新源的存在性；
- 显示、监控、输入和超时数值范围；
- HTTP URL 与 HID VID/PID 格式；
- 已启用命令是否存在文件或候选文件；
- 时间线 STEP、持续时间和消息键；
- 游戏是否缺少可监控的进程与窗口目标。

## 扩展配置模型

为 `LauncherSettings` 或其子模型增加字段后，应依次：

1. 在对应页面加入绑定控件；
2. 在 `ConfigurationDocumentService.Normalize` 中处理可空集合或对象；
3. 在 `ConfigurationValidator` 中加入引用、范围或格式规则；
4. 用现有 `alls-launcher.json` 做打开—预览—另存往返测试；
5. 在 Windows 上执行 `dotnet build ALLS.sln -c Release` 并进行界面检查。
